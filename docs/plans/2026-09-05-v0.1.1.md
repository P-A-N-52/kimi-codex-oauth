# v0.1.1 Implementation Plan

**Goal:** 完成配置校验、凭据权限与卸载、测试与发布准备三项改进。

**Architecture:** 保留 Node >= 18、零外部依赖和现有本地 Responses 代理架构。配置验证与私有文件原子写入抽成小型共享模块，供同步和卸载共用；停止进程使用当前实例的随机控制密钥，避免按进程名批量终止。

**Tech Stack:** Node.js 内置模块、node:test、GitHub Actions。

## 已确认范围

- 用户授权处理审查中的第 2、3、4 项；本次不改变 Responses 端点的调用鉴权。
- 用户报告此前在 macOS、Kimi Code 0.39.0 实测通过；macOS 与 Node 版本未记录。此记录不代替 v0.1.1 回归测试。
- 比较过三种做法：只修改说明（不能修复已复现问题）；重写代理（超出本次范围）；小范围共享安全写入和配置验证（采用）。

## 实施与验证

1. 新增 `bin/private-file.mjs`，原子写入前创建私有临时文件；POSIX 收紧权限，Windows 在写内容前复制原 DACL；失败清理临时文件。使用临时目录测试权限与失败恢复。
2. 新增 `bin/config-file.mjs`，集中 `kimi doctor` / Python tomllib 校验、写前变更检查及配置备份；无校验器或超时拒绝写入。测试不可用、错误、成功及用户并发修改。
3. 调整代理刷新写回与错误日志，加入实例控制；添加安全停止和卸载脚本、命令说明。测试刷新失败不改文件、不泄露凭据、实例身份不符不停止、只删除未引用的受管配置。
4. 更新 setup 入口使用受校验的同步脚本，更新 README、隐私说明、AGENTS、版本元数据及 CHANGELOG。
5. 使用 Node 内置测试跑 Windows/macOS/Linux CI，检查最低 Node 18 与当前维护版本。所有自动测试只使用合成凭据、隔离目录及模拟上游。
6. 审查 diff、执行测试、提交到工作分支并整理 v0.1.1 发布材料；保留可复核的代码、CI 与版本证据。
